# 0041. 간결한 Jira 보고와 주의 항목

## Context

Router의 Jira 댓글은 결과마다 하나씩 달렸고, 무엇을 해야 하는지가 근거 뒤에 나왔다. 관리자 재시도가 같은
이유로 다시 실패하면 같은 실패 댓글이 또 달렸다. 사람이 지금 봐야 할 것(실패, 결정 대기, 범위 이탈, 개별 검토가
필요한 결과, 계약이 빠져 보류된 요청, Jira에 반영하지 못한 보고)은 Jira 댓글·Router 로그·`reports list`·
`holds/readiness`에 흩어져 있었고, 같은 사건이 몇 번 반복됐는지, 해소됐는지, 재발했는지는 남지 않았다.
M4 백로그 M4-09는 "변화 → 영향 → 필요한 사람 행동 → 근거" 순서의 짧은 댓글, 즉시 확인/일반 검토 대기/내부
기록의 구별, 동일 사건의 묶음과 해소·재발 이력, 보고용 추가 LLM 호출 금지를 요구한다.

## Decision

1. **분류**: ADR 0040의 검토 분류를 그대로 쓴다. `immediate` 결과(실패·결정·범위 이탈·고위험·미검증·커밋
   없음·커밋 미보고)와 계약 보완 보류, 막힌 Jira 보고가 **즉시 확인**이다. `standard` 결과는 **일반 검토 대기**다
   (검토 상태와 `review_targets`). heartbeat·임대 갱신·불확실한 쓰기의 재조회·자동 재시도는 **내부 기록**이며
   주의 항목이 되지 않는다. 분류는 일반 코드(`src/router/attention.ts`)가 하고 LLM을 부르지 않는다. 이전 문서의
   "묶음 검토"라는 이름은 쓰지 않는다. 묶음 승인 기능은 없다(F02).
2. **주의 항목**(migration 12, `attention_items`): 사건 키는 이슈 + 종류 + 원인이다. 원인은 실패 이유·질문·이탈
   경로를 소문자화하고 숫자·해시를 지운 형태다. 행에는 승인 id, 분류 근거(한 문장), 증거, 최초·최근 발생,
   발생 횟수, 상태(미해결/해소), 해소 시각과 이유, 이전 발생 링크(`previous_id`)가 있다.
   - 같은 사건이 미해결이면 횟수만 늘린다(`repeated`). 증거나 심각도가 바뀌면 `changed`다.
   - 해소된 사건이 다시 생기면 새 행을 만들고 이전 행에 연결한다(`recurred`).
3. **댓글 억제**: 결과에서 나온 사건이 `repeated`이면 그 결과의 댓글 단계를 빼고 저널에 넣는다. 라벨과 상태
   이동은 그대로 한다. `new`·`recurred`·`changed`는 댓글을 단다. 계약 보완 보류는 기존처럼 같은 요청에 댓글
   하나다(ADR 0034).
4. **해소**: 원인이 사라졌을 때 Router가 기록만 한다.
   - 같은 이슈의 새 승인으로 job이 생기면 이전 승인의 실패·결정·범위 이탈·검토 필요 항목.
   - 같은 이슈의 실행이 성공(또는 계획 완료)하면 실패 항목. 범위 이탈·결정 대기는 성공으로 해소되지 않는다.
     새 승인만 해소한다.
   - 새 결과가 기록되면 이전 결과의 검토 필요 항목(대체됨). PR 머지가 검토 대상과 맞으면(ADR 0040) 그 항목.
   - 계약이 채워져 보류가 풀리면 계약 보완 항목. 막힌 보고가 재시도로 반영되면 그 항목.
   스케줄러는 이 테이블을 읽지 않는다. 해소는 실행 승인을 만들지 않는다.
5. **댓글 형식**: 성공은 "완료 → 검토 분류와 사유 → 다음 행동(PR) → 검토 커밋·고위험 근거 → acceptance별
   판정 → 요약·변경·검증 → 서명(job·attempt·승인·입력 해시)", 실패는 "실패 → 영향(상태·라벨·같은 승인으로 재실행
   없음) → 다음 행동(다시 요청하는 방법) → 실패 이유 → 요약·증거 위치 → 서명"이다. 결정 요청 댓글은 ADR 0036
   형식 그대로다. 로그는 복사하지 않고 위치만 적는다.
6. **조회**: `GET /api/v1/admin/attention?status=open|resolved|all&issue=&kind=`, `ggjira router attention`,
   `router status`의 `needs attention`, 웹 UI 대시보드의 "확인 필요" 카드와 목록, 이슈 화면의 주의 항목.
   읽기 전용이다. 사람이 손으로 해소하는 경로는 두지 않는다(원인을 고치면 해소된다).

## Consequences

- 관리자 재시도가 같은 이유로 거듭 실패해도 Jira 댓글은 하나다. 몇 번 실패했는지는 주의 항목의 횟수로 본다.
- 실패 이유의 숫자만 다른 실패(실패한 테스트 수 등)는 같은 사건이다. 문장이 달라지면 다른 사건으로 새 댓글이
  달린다.
- 계약 보완 보류는 보완 조회마다 횟수가 늘어난다(60초 간격). 댓글은 늘지 않는다.
- DB migration 12가 추가된다. 이전 바이너리는 이 테이블을 쓰지 않는다.
- 요약 알림(digest)은 F07이다.
