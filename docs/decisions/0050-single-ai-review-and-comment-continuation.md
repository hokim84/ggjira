# 0050. 단일 AI 검토와 댓글로 계획 이어가기

## Context

계획 요청과 계획 검토 상태가 분리되어, 선택지 번호를 답한 뒤에도 상태를 되돌려야 했다.
사용자는 AI 상태를 하나로 줄이고 번호 답변·제목/설명 수정·실패 후 재시도로 계획을 이어가기를 원한다.
구현 승인을 댓글로 처리하거나 Router가 작업 중으로 자동 이동하는 기능은 제외한다.

## Decision

- 설정은 `requestStatus` 하나(기본 이름 `AI 검토`)로 계획·질문·승인 대기를 표현한다.
  `planReviewStatus`를 제거하고 설정 오류로 거절한다. 다른 업무 상태와는 여전히 달라야 한다.
- 상태 진입, 정규화된 제목·사용자 설명 변경, 최신 질문의 담당자 번호 답변, 실패 후 담당자의 `재시도` 댓글을
  각각 새 계획 요청으로 기록한다. migration 16의 `planning_requests`는 입력 해시와 원문 스냅샷,
  상태 진입 ID, 소스 댓글 ID, 선택 내용을 보존한다. 요청 ID는 Worker의 기존 approvalId로 전달한다.
- Router가 렌더링한 관리 계획 블록은 계획 입력 해시와 수정 감지에서 제외한다. 그 안의 편집은 계약 수정이 아니다.
  구현 계약은 계속 Router DB의 승인된 계획이다. 구현 단계의 기존 입력 변경 검사는 유지한다.
- 자동 재계획은 현재 Jira 담당자의 `2`·`2번` 또는 기존 `Decision: <id>` 형식의 유효 선택만 받는다.
  일반 댓글과 자유 서술은 자동 신호가 아니다. 질문 이후 첫 유효 답변을 한 번만 소비한다.
  Router 보고 마커·서명이 있는 댓글은 작성자가 담당자와 같아도 답변이 아니다.
- `재시도`는 댓글 전체가 일치하고 계획 실패 이후 작성된 경우만 받는다. 구현 재시도나 불명확한 실행의 복구는
  기존 관리자 절차다. Jira 반영 실패는 `reports retry`로 반영만 복구한다.
- 입력 변경 중인 실행은 취소를 요청하고 종료 확인 전에는 다음 작업을 실행하지 않는다. 오래된 결과·보고는
  최신 요청 ID·입력·상태를 재검사해 반영을 차단한다. recovery_required는 자동으로 다시 실행하지 않는다.
- 계획 완료·질문 보고는 Jira 상태를 이동시키지 않는다. 계획의 모든 보고가 적용된 뒤 AI 검토에서 준비됨을
  기록한다. 그 시점에 관찰한 changelog ID를 저장하고, 그 이후의 AI 검토 → 작업 중 이동만 승인한다.
  최신 입력과 계획 버전이 달라지거나 계획이 질문 대기라면 승인을 거절한다.
- 댓글 이벤트도 재평가를 깨운다. 실제 판단은 Jira 재조회 후 수행하고 기존 polling을 유지한다.
  댓글 조회는 페이지를 끝까지 읽어 최근 답변이 첫 페이지 밖에 있어도 놓치지 않는다.
- 이슈 조회의 stage에 계획 실패·복구 대기를 추가한다. 승인 대기는 Jira 보고까지 완료된 경우만 표시한다.
- upgrade 시 기존 job이 있는 이슈를 `planning_baselines`에 기록하고 열린 계획·배포 승인을 닫는다.
  이전 요청은 자동 채택하지 않으며 cutover 이후 명시적으로 다시 위임해야 한다.

ADR 0044·0047의 계획 완료 시 상태 이동, 상태 진입만으로 계획 요청을 식별하는 규칙,
ADR 0049의 답변 뒤 상태 재이동 및 자유 서술 답변의 자동 수집을 이 범위에서 대체한다.

## Consequences

AI 전용 상태는 하나이며 질문 답변에 상태 이동이 필요 없다. 구현 승인은 여전히 사람의 수동 이동이다.
Router/Worker wire 프로토콜과 envelope 구조는 그대로이며 추가 LLM 호출을 도입하지 않는다.
전환 전 활성 실행과 미완료 보고를 정리하고 DB·설정을 백업해야 한다(runbook §36).
구버전으로 복귀하려면 백업한 DB·설정을 함께 복원한다. 실제 Jira 상태는 별도로 복구한다.

검증: Router·Jira client·Fake 통합 등 Worker 파일을 제외한 504개 테스트 통과. 타입·lint·format 검사와
build 통과. 전체 check는 Windows의 `spawn EFTYPE` 15개와 프로세스 트리 종료 테스트의 timeout 2개로
미통과했다. 종료 테스트 2개는 단독 실행에서도 재현했다. 실제 Jira·AI CLI 연동과 운영 DB 이관은 실행하지 않았다.
