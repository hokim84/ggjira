# 0053. 칸반 진행 표시와 선택적 AI 리뷰

## 결정

Router 설정 버전은 6, Worker wire protocol은 5다. 기존 설정을 암묵적으로 변환하지 않는다.
ADR 0044·0050·0051의 부모 승인, 단일 계획 상태, 필수 품질 평가와 PR 머지 후 자동 Done을 대체한다.

| 설정 | 기본 상태 | 진입 |
| --- | --- | --- |
| requestStatus | AI 계획 | 사람이 계획 요청 |
| planningInProgressStatus | AI 계획중 | 워커가 실제 계획 실행을 시작 |
| inProgressStatus | AI 구현 | 사람의 작업별 승인, 첫 자식 실행 시 부모 자동 표시 |
| integrationPendingStatus | AI 통합 대기 | 구현·작업 검증 성공, 사람의 PR 머지 대기 |
| implementationCompleteStatus | AI 구현 완료 | 머지·신뢰된 통합 검증 성공 |
| reviewStatus | AI 리뷰 | 사람이 선택적으로 평가 요청 |
| doneStatus | Done | 사람이 최종 완료 |

제목·설명은 직접 구현의 승인 범위다. 게시된 단일 작업 계획이 최신이면 그 계약을 사용한다.
부모의 계획 게시와 실행 후보 탐색 순서가 바뀌어도 같은 계약이 유지되어야 한다.
자식은 각각 승인하고 의존 작업의 통합을 기다린다. 부모는 조정만 하며,
구현 완료·리뷰 후의 명시적 재작업 요청에서는 기존 자식을 보존하고 통합 수정을 직접 실행할 수 있다.
계획 번호 답변과 입력 수정으로 계획을 이어가되 자동 상태 이동은 새 요청으로 해석하지 않는다.

## 통합과 리뷰

`integration_check`는 추가 모델 호출 없이 격리된 Git worktree에서 신뢰된 `validateCommand`를 실행한다.
검토 대상 head와 실제 merge commit, 대상 브랜치, 최신 구현 결과를 확인한다.
검증 명령 미설정·실패·대상 변경은 자동 완료하지 않는다. 자식 재작업 시 부모의 통합 증거를 다시 확인한다.
각 검증은 구현 결과 세대에 연결하므로 이전 검증 결과나 오래된 보고가 새 작업을 완료할 수 없다.

코드 변경 없는 작업은 변경 불필요 근거(`implementation.noChangeReason`) 또는 Git 무변경 증거,
변경 경로 없음, 성공한 결과 검증을 요구한다. 비 Git 저장소라는 이유만으로 무변경으로 취급하지 않는다.

`quality_review`는 부모·자식·단독 작업에 공통으로 사용하는 읽기 전용 권고 평가다.
기술 부채·결함·근거·영향·수정 제안을 댓글로 게시하고 AI 리뷰에 유지한다.
지적 판정·자동 수정 자식·강제 후속 이슈를 만들지 않으며, 리뷰는 부모 완료 조건이 아니다.
수정은 사람이 AI 구현으로, 재분해는 AI 계획으로, 최종 완료는 Done으로 옮긴다.

실패는 현재 단계에 `ggjira-failed`, 질문은 `ggjira-needs-answer`로 표시한다.
종료가 확인된 실패는 담당자의 새 `재시도` 댓글로 해당 단계만 다시 실행한다.
불확실한 실행은 기존 관리자 복구 절차를 거친다. 늦은 보고·중복 이벤트·재시작은 보고 저널과
상태 진입 ID·입력 해시·구현 세대를 다시 확인하여 중복 실행과 역전이를 막는다.

## 초기 연결과 적용

설정 마법사는 프로젝트 선택 시 누락된 AI 상태와 전이를 자동 추가하고, 추가 전 안내와 결과를 표시한다.
저장 직전 다시 확인하여 Jira 적용 대기나 권한 오류를 성공으로 기록하지 않는다.
기존 상태·전이·규칙·워크플로우 버전을 보존하고, 여러 프로젝트가 공유하는 글로벌 워크플로우는 자동 수정하지 않는다.
운영 Router는 계속해서 워크플로우를 수정하지 않으며 설정의 명시적 자동 구성 동작만 제공한다.
Jira 시스템 상태의 번역이 비교 결과를 바꾸지 않도록 API 응답 언어를 en-US로 고정한다.

Task와 Subtask에서 일곱 상태를 사용할 수 있어야 한다. 보드 열은
해야 할 일 → AI 계획 → AI 계획중 → AI 구현 → AI 통합 대기 → AI 구현 완료 → AI 리뷰 → Done 순으로 구성하고
레이블을 카드에 표시한다. 최초 연결 메시지는 보드 열 설정도 안내한다.
기존 테스트 데이터의 호환성은 지원하지 않는다. 전환 전에 실행과 spool을 정리하고 Router·Worker를 함께 업데이트한다.

검증은 Fake Jira·임시 SQLite·로컬 Git 및 실제 HTTP 연결로 수행한다. 실제 Jira 상태 구성과 보드 배치는
별도로 확인하며 실제 AI CLI 실행 여부는 자동 테스트 결과와 구분한다.
