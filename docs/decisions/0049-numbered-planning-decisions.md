# 0049. 계획 결정은 선택지 번호로 답한다

## Context

계획 검토의 `Decision: <선택지 id>` 안내는 키워드 입력을 요구하고 어떤 ID를 적을지도 모호했다.
사람은 질문 댓글에 보이는 선택지 번호만 입력하기를 원한다.

## Decision

- 선택지는 표시 순서대로 `1. 제목`, `2. 제목`으로 렌더링한다. 추천이 optionId이면 같은 번호·제목으로 표시한다.
- 계획 질문 댓글에 `decisionOptions:` JSON 배열로 표시 순서와 원래 optionId의 대응을 기록한다.
  `planVersion:`·`decisionId:`와 함께 언어와 무관한 기계 판독 필드다.
- 사람은 `2` 또는 `2번`을 댓글로 남긴 뒤 요청 상태로 옮긴다. 번호는 최신 질문의 선택지에만 대응한다.
  범위 밖 번호는 답으로 인정하지 않고, 이후 올바른 댓글을 찾는다.
- PM 프롬프트에는 사람의 원문 답과 최신 결정 요청을 함께 전달한다. 번호만으로 선택의 의미가 사라지지 않는다.
- 이전 `Decision: <id>`와 자유 서술 답은 계속 읽는다. 번호 매핑이 없는 이전 질문은 기존대로 처리한다.
- 구현 중 중단의 선택지도 번호로 표시하지만, 재계획하려면 설명을 고쳐 요청해야 하는 절차는 유지한다.

ADR 0048의 결정 답에 `Decision:` 형식을 요구하는 부분을 대체한다.

## Consequences

추가 LLM 호출·DB migration·Worker 프로토콜 변경은 없다. 새 안내는 새로 작성하는 댓글부터 적용된다.
기존 질문 댓글은 자동으로 수정하지 않는다. 새 번호 답을 PM에 전달하려면 Router와 Worker를 함께 갱신한다.

검증: 관련 테스트 4개 파일 59개 통과. 타입·lint·format 검사와 build 통과. 전체 `npm run check`는
608개 중 589개 통과, 19개 실패(spawn EFTYPE·시간 초과 등)로 전체 통과하지 못했다.
실제 Jira·AI CLI 연동은 실행하지 않았다.
