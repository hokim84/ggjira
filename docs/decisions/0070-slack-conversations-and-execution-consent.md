# ADR 0070: Slack DM 작업 대화와 자동 구현 승인

## Context

플랜 선택지를 담당자가 Slack에서 답하고, 질문·답변을 Jira에도 남겨야 한다. 추가 질문 없는 플랜은
담당자의 별도 Jira 이동 없이 구현을 시작한다. 사용자가 승인한 정책이며 ADR 0044/0047의 개별 상태 이동
승인 규칙에 Slack 연동 작업만 예외를 추가한다.

## Decision

- Router만 Slack HTTPS API와 서명 검증된 `/webhooks/slack`을 사용한다. 단일 Slack team을 지원한다.
  Bot Token과 Signing Secret은 환경변수 또는 router.env로 관리하며 관리 API에는 값을 노출하지 않는다.
- workspace 활성화 시점을 영속 기록한다. 이후 요청이며 Jira 담당자와 Slack 사용자 연결이 있는 작업만
  DM 대화와 자동 승인을 사용한다. 기본값은 비활성이다. 기존 대기 작업은 자동 승인하지 않는다.
- 계획 요청별 DM 스레드를 만들고 답변에 따른 후속 계획·구현·통합 결과를 누적한다. 새 재계획 요청은
  새 대화다. Slack 질문·답변은 Jira에도 기록한다. 선택 버튼, 번호, 자유 텍스트를 지원하며
  봇이 복사한 Jira 댓글은 사람의 발언으로 간주하지 않는다.
- SQLite inbox/outbox, 질문별 답변, 스레드 연결과 승인 저널을 사용한다. 수신 이벤트를 먼저 저장하고
  HTTP 응답 후 비동기 처리한다. 현재 담당자·질문·플랜·요구사항·상태를 검증하고 중복 답변을 배제한다.
- `planned`이며 모든 필수 Jira 보고가 반영되고 최종 플랜이 Slack에 전달된 경우에만 자동 실행 승인을
  기록한다. 분할 플랜은 현재 버전의 하위 작업을 승인한다. 실행 계약·의존성·가용성·중단 복구 규칙은 유지한다.
- 구현 중 결정 요청도 스레드에서 받는다. 답변을 보존하고 재계획을 요청한 뒤, 새 플랜이 확정되어야
  다시 구현한다. 실패·복구 필요 상태를 알림 재시도로 재실행하지 않는다. 최종 Done은 사람의 결정이다.

## Consequences

Slack을 활성화하면 해당 workspace의 연결된 담당자는 질문 없는 플랜의 자동 구현에 동의한 것으로 본다.
환경 설정 화면에 이를 명시한다. 설정·이벤트·발신 오류와 누락된 사용자 연결은 관리 화면에서 확인한다.
Slack이 실패하면 초기 자동 구현은 보류하지만 이미 진행 중인 작업은 알림 오류 때문에 중단하지 않는다.
Slack 전달 직후 프로세스가 죽어 로컬 확인이 유실되면 알림이 중복될 수 있다. 재전송에는 안정적인
client_msg_id를 사용하며, 중복 알림이 중복 계획·실행 승인으로 이어지지는 않는다.
